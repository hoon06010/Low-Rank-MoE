# Shared 용량은 routed expert를 줄이는 방식을 바꾸는가?

작성: 2026-11-13. 연구 질문 정교화안. 로컬 실험 원자료·구현과 1차 문헌을 다시 확인했다.
새 언어 모델 학습은 실행하지 않았다. 아래 추가 측정은 학습 없는 합성 입력 초기화 진단이다.
이 문서는 후속 연구 방향 제안이며 기존 seed·recipe·실행 순서·예산 승인을 자동 변경하지 않는다.

## 1. 지금 가장 먼저 답할 질문

> 같은 총 파라미터와 주어진 학습 토큰 예산에서 shared FFN에 용량을 더 배정할 때, routed FFN을 **넓지만 저랭크로 유지하는 방식**과 **좁은 dense FFN으로 만드는 방식** 중 어느 쪽이 더 좋은 품질을 얻는가? 그 선택은 shared 용량에 따라 달라지는가?

쉽게 말하면, 모델을 작게 만들어야 할 때 전문가의 **변환 방향을 제한할지**, **중간 특징 수를 줄일지**를 고르는 문제다. 모든 토큰이 사용하는 shared 경로의 크기가 이 선택을 바꾸는지 확인한다.

주 결과는 동일 저장 파라미터·동일 토큰 수에서의 품질 비교다. **같은 학습 FLOPs에서도 유리한가**와 **입력에 맞춰 expert를 고르는 이득이 남는가**는 각각 추가 비용 비교와 routing 대조로 답한다. 이 조건들을 확인하기 전에 질문에 “효율 향상”이나 “전문화 보존”이라는 결론을 넣지 않는다.

이 질문에 답하면 설계자는 제한된 저장 용량에서 다음 중 하나를 고를 근거를 얻는다.

- 넓은 저랭크 routed + 큰 shared
- 좁은 dense routed + 같은 크기의 shared
- routed 용량을 더 유지하는 배분
- 조건부 선택의 이득이 없다면 shared-only 경계

고정 예산의 미시험 조합을 하나 추가하는 것이 연구의 이유는 아니다. **같은 예산을 아끼는 두 방법이 서로 다른 표현 제약을 만들고, shared 용량이 그 제약의 대가를 바꿀 수 있다**는 것이 조사할 이유다. 어느 방법이 이긴다는 전제는 두지 않는다.

## 2. 문제에서 설계까지의 연결

### 출발 문제: 저장할 용량과 매번 계산할 용량은 다르다

MoE는 많은 expert를 저장하되 각 토큰에서는 일부만 사용한다. 저장 예산을 줄이려면 expert를 줄이거나, 폭을 줄이거나, 행렬을 factorize하거나, 공유 구조를 도입할 수 있다. 현재 연구는 그중 **routed rank 제한과 dense 폭 축소**를 비교하고, 절약한 파라미터를 shared 경로로 옮기는 선택을 조사한다.

고정 파라미터는 저장 weight 용량이 제한된 상황을 택한 연구 조건이다. 현재 작은 모델의 실제 운영에서 저장 메모리가 주 병목임을 측정했다는 뜻은 아니다. 계산량이 유일한 제약인 상황에 답하려면 동일 FLOPs 비교를 주 결과로 삼아야 한다. 파라미터 수를 peak GPU memory와도 동일시하지 않는다.

Shared는 모든 토큰에서 실행되므로 큰 shared는 더 많은 항상 활성 용량을 제공한다. 동시에 더 많은 연산을 요구한다. “공통 지식을 담당한다”는 것은 가능한 역할 설명이며, 항상 실행된다는 구조적 사실만으로 그 역할이 입증되지는 않는다.

### 조사할 가설

넓은 저랭크 FFN은 적은 입출력 방향으로 많은 중간 비선형 특징을 조합한다. 좁은 dense FFN은 중간 특징 수는 적지만 대응하는 저랭크 모델보다 넓은 출력 방향을 허용한다. 큰 shared 경로가 있을 때 전자의 제약이 덜 불리해질 수 있다는 것이 **가설**이다.

반대도 가능하다. 입력별 변환에 많은 독립 방향이 필요하거나, factorized 학습이 불리하거나, shared 확대가 단순히 dense 계산량만 늘린다면 좁은 dense가 같거나 더 좋을 수 있다. 이 경우에도 “어떤 축을 줄이면 안 되는가”라는 설계 판단이 남는다.

## 3. 왜 low-rank인가: 구조가 보장하는 것부터 구분한다

현재 routed SwiGLU는 gate/up/down을 모두 rank r로 매개변수화한다.

\[
E(h)=B_d A_d\left[\operatorname{SiLU}(B_g A_g h)\odot(B_u A_u h)\right].
\]

이는 현재 [구현](../src/model.py)의 구조를 식으로 쓴 것이다. 이 식에서 다음은 수학적으로 따라온다.

- 단일 expert 출력은 고정된 col(B_d)에 있으므로 그 부분공간 차원은 최대 r다.
- 단일 expert는 A_g h와 A_u h에 의존하므로 입력 의존 부분공간 차원은 최대 min(d,2r)다.
- router는 원래 d차원 입력을 읽는다. 따라서 전체 routed 경로의 입력 정보가 2r차원 이하라고 말할 수 없다.
- 선택 expert 집합이 고정되면 routed 출력은 최대 min(d,Kr)차원의 합 부분공간에 있다. 선택 집합 전체에 걸친 span은 min(d,Nr)까지 가능하다.
- attention·shared·residual을 포함한 전체 모델이 rank r로 제한된다는 뜻은 아니다.

Bias 없는 SwiGLU의 파라미터 수는 다음과 같다.

\[
p_{\rm LR}=3r(d+m), \qquad p_{\rm DW}=3dm'.
\]

같은 routed 예산을 맞추면 m'=r(d+m)/d다. 현재 d=384, m=768이므로 m'=3r다.

| 방법 | 중간 비선형 폭 | 단일 expert 출력 span의 상한 | 예산을 아끼는 방식 |
|---|---:|---:|---|
| LR, r=32 | 768 | 32 | 선형 변환을 factorize |
| DW, 대응 예산 | 96 | 96 | 중간 폭 자체를 축소 |
| LR, r=64 | 768 | 64 | 선형 변환을 factorize |
| DW, 대응 예산 | 192 | 192 | 중간 폭 자체를 축소 |

폭 768은 독립적인 정보 방향 768개가 보장된다는 뜻이 아니다. 각 방법의 표현 가능한 함수 사이에 이 표만으로 우열이나 포함 관계가 성립하지 않는다.

**따라서 low-rank를 시험할 이유는 “전문 지식은 원래 저차원”이어서가 아니다. 중간 비선형 폭과 선형 변환의 자유도를 다르게 줄이는 방법이기 때문이다.** 큰 shared가 이 교환의 손실을 줄이는지는 실제 LR/DW 비교로 확인해야 한다.

“shared가 있어서 조건부 출력 차원이 작아도 충분하다”까지 설명하려면 down-only 저랭크 대조가 필요하다. 현재 세 행렬을 모두 factorize한 비교는 입력 제한·출력 제한·최적화 방식이 함께 바뀐다.

## 4. 각 설계를 남기는 이유와 포기할 조건

| 선택 | 현재 필요한 이유 | 이 선택으로 보장되지 않는 것 | 판단할 증거 |
|---|---|---|---|
| native pretraining | 이미 학습된 큰 모델의 압축·복구 능력과 처음부터의 배분을 구별 | 대규모 학습에도 유효함 | 같은 데이터·학습량에서 처음부터 학습 |
| dense shared | 항상 활성 경로에는 별도 factorization 병목을 강제하지 않고 routed 제한 조사 | 공통 기능은 반드시 고차원 | rank 배치 자체를 주장할 때 역배치 대조 |
| LR routed | 넓은 nonlinear 폭을 유지하며 입출력 방향과 파라미터 축소 | 전문성 보존·속도 개선 | 같은 예산 DW 대비 |
| gate/up/down 같은 r | 변수 수를 줄이고 명료한 예산 비교로 시작 | 최적 factorization 위치 | 메커니즘 주장 때 projection별 대조 |
| N=8, K=2 고정 | expert 수와 선택 횟수 변화가 섞이지 않도록 통제 | 최적 N/K·모든 MoE에 일반화 | 첫 질문에서는 고정, 전이 주장 때 확장 |
| shared 용량 변화 | 항상 쓰는 용량과 선택적으로 쓰는 용량의 배분 조사 | 실제 공통/전문 지식 분리 | 품질·routing 대조·별도 기능 분석 |
| 동일 총 파라미터 | 저장할 weight 용량을 맞춘 비교 | 동일 FLOPs·peak memory·속도 | 별도 비용 집계와 compute-matched 학습 |
| 동일 학습 토큰 | 데이터 노출량을 맞춘 비교 | 충분한 학습·동일 학습 비용 | 학습 길이와 동일 FLOPs 비교 |
| LR/DW 각 2×2 | rank/폭 축소와 shared 확대를 분해 | 상호작용의 내부 메커니즘 | 전체 원 loss와 사전 대비 |
| 복수 초기화 seed | 초기화에 따른 변동 확인 | 데이터·규모·환경 일반화 | 완전한 paired block 및 환경 기록 |
| next-token CE | 동일 tokenizer에서 민감하고 직접적인 학습 목표 비교 | 추론·전문 지식·다운스트림 능력 | 별도 task 근거가 있을 때만 확장 |
| 작은 모델·8.4M tokens | 자원 안에서 구현·탐색 신호 확보 | 최종 설계 결론을 내릴 충분한 학습량 | 학습 길이·규모 검증 |

SwiGLU, RoPE, 층 수, tokenizer, 학습률 등의 기존 선택은 비교를 가능하게 하는 고정 배경과 운영상 선택이다. 모든 값에 새로운 이론적 필연성을 붙이지 않는다. 구조상 이유가 있는 선택, 공정 비교를 위한 통제, 자원 때문에 정한 선택을 구분해 기록한다.

현재 shared와 routed는 **같은 정규화 입력을 병렬로 받고 출력을 합산**한다([TransformerBlock](../src/model.py)). “shared가 먼저 공통 지식을 계산하고 routed가 그 잔차를 입력받는다”는 구조가 아니다.

## 5. 현재 관찰은 어디까지인가

Stage C seed17과 seed401의 원 JSON·metrics 최종행을 다시 대조했다. 조건당 8,388,608 targets / 2,048 steps, dev 65,536 targets다. H/L은 routed rank 64/32, S/L은 shared 수 2/5이며 shared 하나의 폭은 256이다.

| 조건 또는 대비 | seed17 | seed401 |
|---|---:|---:|
| HL CE | 6.05776107 | 6.05213559 |
| HS CE | 6.11435759 | 6.10328890 |
| LS CE | 6.13254436 | 6.12923248 |
| LL CE | 6.07361295 | 6.06640364 |
| G_low = LS−LL | +0.05893141 | +0.06282885 |
| G_high = HS−HL | +0.05659652 | +0.05115331 |
| I_LR = G_low−G_high | +0.00233489 | +0.01167554 |
| Δ_budget = LL−HS | −0.04074464 | −0.03688526 |

단위는 nats/target이며 CE는 낮을수록 좋다. 원자료: [Stage C 보고서](c_execution_2026-10-01.md), [seed401 보고서](seed_repeat_c/seed-401/adamw-completion-2026-10-09.md), [Stage C metric 디렉터리](../artifacts/kaggle/stage-c-final/C/), [seed401 원 metric 디렉터리](seed401_spectron/execution-2026-10-09/adamw-anchor/main/).

현재 가능한 해석은 다음과 같다.

1. 같은 shared 용량에서는 낮은 rank가 두 seed 모두 더 나빴다. 낮은 rank 자체의 우위는 관찰되지 않았다.
2. HS→LL에서는 shared 확대 이득이 rank 축소 손해보다 컸다. 이 유한 학습 조건에서 두 끝점 사이의 재배분이 유리했다.
3. shared 확대는 높은 rank에서도 상당한 이득이 있었다. low-rank만 특별히 보완했다는 설명은 아직 약하다.
4. I_LR는 두 최종 끝점에서 양수지만 크기가 다르며, seed17의 1M·2M·4M 중간 평가에서는 음수였다. 최종 끝점을 유지하고 좋은 checkpoint를 골라 결론내리지 않는다.
5. LR/DW 대조, 조건부 routing 가치, 동일 FLOPs 우위는 아직 확인되지 않았다.

두 실험의 공통 소스·training 설정과 data/eval identity는 대응하지만 실행 환경은 다르다. seed17은 Python 3.12.13/PyTorch 2.10.0, seed401은 Python 3.13.15/PyTorch 2.11.0이다. seed17은 탐색 seed이며 둘을 합쳐 사전 확증 반복으로 부르지 않는다.

로컬 기록상 seed402는 준비 확인·운영 adapter 보완 대기이며 미시작이다([상태](../docs/public_release.md)). Spectron은 학습 전 자원 게이트에서 멈췄고 optimizer step 0이다([실행 보고](seed401_spectron/execution-2026-10-09/execution-report.md)). 이를 저랭크 optimizer의 학습 실패로 해석하지 않는다. 원격 GPU 현재 상태는 이번에 조회하지 않았다.

## 6. 왜 지금의 좋은 결과만으로 충분하지 않은가

### 6.1 항상 실행되는 계산이 증가했다

총 expert 예산 P_E, shared 파라미터 P_s를 사용하면

\[
P_E=P_s+Np_r,\qquad
P_{\rm act,E}=P_s+Kp_r
=\frac KN P_E+\left(1-\frac KN\right)P_s.
\]

고정 P_E와 N/K 아래 shared를 늘리면 K<N인 한 활성 expert 파라미터가 늘어난다.

| 항목 | HS | LL |
|---|---:|---:|
| 총 파라미터 | 37,016,832 | 37,016,832 |
| 대수적 전체 활성 파라미터 | 29,054,208 | 33,035,520 |
| 층당 활성 expert 파라미터 | 1,032,192 | 1,695,744 |

expert 부분은 64.29%, 전체 대수적 활성 수는 약 13.70% 증가한다. 전체 FLOPs나 실제 시간 증가율은 아니다. 같은 저장 용량에서 더 많은 연산을 사용한 효과와 구별해야 한다.

DW는 대응 LR 셀과 shared·총/활성 파라미터를 맞춘다. 다만 서로 다른 GEMM 형태와 nonlinear element 수 때문에 실제 FLOPs·속도까지 자동으로 같지는 않다.

### 6.2 양의 상호작용은 내부 역할 분리의 증명이 아니다

I_LR>0은 큰 shared에서 낮은/높은 rank의 손실 격차가 작아졌다는 운영적 관측이다. 단순한 용량 증가의 한계효용 체감으로도 발생한다.

설명용 가상 모형에서 네 셀의 층당 expert 예산 비율은 LS:HS:LL:HL = 5:8:8:11이다. 손실이 구조적 역할 분리 없이 L(P)=c+a/P, a>0만 따른다고 가정해도

\[
I=a(1/5-2/8+1/11)=9a/220>0.
\]

LR과 DW의 곡률 계수 a가 다르면 J=I_LR−I_DW도 양수가 될 수 있다. 이는 실제 데이터를 적합한 결과가 아닌 논리적 반례다. 따라서 I/J는 가족별 상대 상호작용을 나타내며 “shared는 공통 지식, routed는 전문 지식”을 입증하지 않는다.

### 6.3 shared 수와 초기 출력 크기가 함께 변한다

현재 SharedExpertGroup은 각 shared FFN을 같은 depth scale로 초기화하고 출력을 합한다. 개수에 따른 합 출력 정규화가 없다. 독립 초기화의 단순 기대에서는 S=2→5일 때 출력 RMS가 sqrt(5/2)≈1.581배가 된다. 이는 원래 계획 §9에서도 구별하도록 요구했던 항목이다.

이번에 학습 없이 실제 SharedExpertGroup 구현을 CPU에서 호출했다. RMS=1로 정규화한 합성 Gaussian 입력 512×384, 입력 seed 20261113, 모델 seed 17/401/402, layer index 0/3/5, depth scale=1/sqrt(12), 로컬 PyTorch 2.9.1을 사용했다.

| seed | layer 0의 RMS 비 | layer 3의 RMS 비 | layer 5의 RMS 비 |
|---|---:|---:|---:|
| 17 | 1.580525 | 1.587418 | 1.585189 |
| 401 | 1.582507 | 1.587456 | 1.583130 |
| 402 | 1.570399 | 1.586446 | 1.587912 |

비는 S=5의 RMS / S=2의 RMS다. 이 진단은 **초기 shared 출력 크기 변화가 실제 구현에서도 나타난다**는 것만 보여준다. 실제 문장 입력·학습된 모델에서의 측정이 아니며, CE 차이의 원인 또는 크기를 추정하지 않는다. seed402 학습을 수행했다는 뜻도 아니다.

후속 설계에서는 실제 초기 shared/routed RMS·초기 gradient/update 크기를 확인하고, 필요하면 공통 branch-scale 규칙을 사전에 정한 별도 민감도 실험을 둔다. 예를 들어 기준 S0=2에 대해 sqrt(S0/S)를 shared 합 출력에 곱하는 규칙은 진단 후보지만 최적 초기화라는 보장은 없다. 기존 완료 실험과 frozen recipe에 소급 적용하지 않는다. 표현 가능한 함수의 동등성은 초기화와 optimizer 동역학의 동등성을 뜻하지 않는다.

### 6.4 짧은 학습의 유리함일 수 있다

Shared는 모든 토큰에서 실행되지만 routed expert는 선택된 토큰에서 실행된다. 큰 shared의 이득이 빠른 학습에 따른 것인지, 더 긴 학습에서도 유지되는 배분 이득인지 현재 끝점만으로 알 수 없다. 이는 문헌에서 학습 길이에 따른 dense/MoE 순위 변화가 보고된 이유와도 연결된다.

현재 마지막 평가 구간에서도 CE가 내려갔다. 이를 미수렴의 엄밀한 판정으로 쓰지는 않지만 수렴한 표현력 비교라고 부를 근거는 없다. 더 긴 실험은 같은 8M 데이터를 반복하는 방식과 새로운 학습 토큰을 추가하는 방식을 구별하고, 종료 토큰에 맞춘 schedule을 새로 정해야 한다.

## 7. 질문에 답하는 최소 실험과 판단 순서

기존 [실험계획](../experiment_plan.md)의 I_LR/I_DW/J/G_low/Δ_budget 정의를 유지한다. 주 예산 비교는 HS↔LL 대각선이며, 2×2 전체는 같은 총 파라미터가 아니다. LS/HL은 원인을 분해하기 위해 의도적으로 예산 밖에 둔 보조 셀이다. LR의 각 셀과 대응 DW 셀은 서로 예산을 맞춘다. 이번 문장 정교화를 과거 결과에 대한 새로운 사전등록으로 포장하지 않는다.

주 질문에 직접 대응하는 비교는 각 고정예산 배분점의 family 차이다.

\[
D_{HS}=L_{\rm LR,HS}-L_{\rm DW,HS},\qquad
D_{LL}=L_{\rm LR,LL}-L_{\rm DW,LL}.
\]

음수이면 해당 배분점에서 LR의 CE가 더 낮다. D_LL−D_HS는 **배분점에 따라 LR/DW 상대 성능이 얼마나 달라지는지**를 나타낸다. 두 D의 부호가 같으면 이득의 크기는 달라도 우세 방법은 같다. 방법 선택의 역전을 말하려면 각 차이의 불확실성과 사전에 정한 실질적 차이 기준까지 확인해야 한다.

이 대각선에서는 shared와 rank/폭 예산이 함께 바뀐다. 따라서 D_LL−D_HS를 shared 단독의 인과효과라고 부르지 않는다. 기존 J는 예산 밖 LS/HL까지 사용하는 별도의 상호작용 대비다. 주 배분 비교와 보조 원인 분해를 구분해 둘 다 원 loss와 함께 보고한다. 위 D 대비는 이번 후속 설계 제안이며 과거 사전 대비였다고 소급하지 않는다. 기존 비열등성 허용치 ε_budget/ε_DW를 새로운 “선택 역전” 기준에 자동 전용하지 않는다.

| 순서 | 할 일 | 제거할 불확실성 | 결과가 반대이면 |
|---|---|---|---|
| 1 | 원 loss·곡선·예산·초기 branch scale 감사 | 무엇이 함께 변했는지 | 용량만의 효과라는 표현을 제한 |
| 2 | 대응 DW 네 셀의 공정한 탐색·비용 준비 | 왜 하필 factorization인가 | LR 고유 필요성을 주장하지 않음 |
| 3 | LR/DW 여덟 셀을 독립 seed·동등 tuning 예산으로 반복 | 차이와 상호작용의 재현성 | 미지지와 정밀도 부족을 구분 |
| 4a | 대표 배분의 동일 학습 FLOPs 비교 | 더 많은 활성 연산의 대가 | 같은 토큰의 품질–계산량 교환으로 보고 |
| 4b | 입력 독립 균형 routing으로 처음부터 학습; SHARED_ONLY 경계 | 조건부 expert 선택이 필요한가 | 역할 분리·전문화 설명을 제한 |
| 4c | 학습 길이 및 초기 scale/optimizer 민감도 | 짧은 학습·특정 recipe에 의존하는가 | 해당 조건의 현상으로 범위를 좁힘 |
| 5 | 효과가 남고 출력 차원 설명이 필요할 때 down-only와 rank grid | 무엇의 저차원성이 중요한가 | all-three 구조 비교 수준으로 한정 |

4a–4c는 주장에 따라 필요한 분기다. 모든 조합을 한꺼번에 실행하지 않는다. 기존 seed402 반복은 같은 LR 현상의 재현성에는 도움되지만, 그것만으로 “왜 LR인가”에는 답하지 못한다. 기존 승인된 실행 순서는 이 문서로 임의 변경하지 않으며, 위 표는 다음 설계를 정할 때의 연구적 우선순위다.

J를 보고하려면 LR/DW 핵심 여덟 셀이 필요하다. HS/LL 몇 점만으로 J 전체를 대신하지 않는다. family별 학습률이 다르면 결과는 동등 tuning 기회를 준 recipe 비교이고, 공통 recipe 여덟 셀을 추가해도 시험한 그 recipe 범위의 강건성이다. optimizer 전반에 독립적인 구조 효과라고 일반화하지 않는다.

최소 rank나 보편적 최적 배분은 현재 주 질문에서 제외한다. 전자는 shared를 고정한 rank grid와 품질 기준·불확실성이 필요하고, 후자는 독립 규모·데이터·학습 예산에서의 검증이 필요하다. 두 끝점만으로 내부 최적값을 찾았다고 하지 않는다.

## 8. 결과에 따라 남길 기여

- **LR/DW 차이가 배분점에 따라 달라짐:** 시험한 예산·학습량에서 두 매개변수화의 상대 성능이 배분에 의존함을 보인다. 우세 방법의 역전 여부와 shared 단독 효과는 별도로 판정한다.
- **LR와 DW가 비슷함:** 좋은 결과의 핵심은 저랭크 고유 성질보다 일반 용량 재배분일 수 있다. LR라는 이름을 유지하려고 결론을 과장하지 않는다.
- **동일 FLOPs에서 이득이 사라짐:** 같은 토큰 수에서 추가 활성 계산을 동반한 품질 개선으로 주장을 한정한다. FLOPs를 맞추면 토큰량·schedule도 달라질 수 있어 추가 계산만이 원인이라고 단정하지 않는다. 계산 효율 개선으로 부르지 않는다.
- **학습된 routing이 입력 독립 routing보다 낫지 않음:** 해당 설정에서 입력별 선택의 추가 가치가 확인되지 않았다. 모든 MoE의 무용함을 뜻하지 않는다.
- **scale 통제나 긴 학습에서 효과가 바뀜:** 초기화·학습 예산 의존성이 중요한 결과다. 그 경계를 설명하는 연구로 범위를 좁힌다.
- **차이가 작고 불확실함:** 동등성을 증명한 것으로 바꾸지 않는다. 현재 정밀도에서 설계 선택을 바꿀 충분한 증거가 없다고 보고한다.

## 9. 연구 소개로 바로 사용할 문단

MoE에서 파라미터를 줄이는 방법은 하나가 아니다. Routed FFN의 폭을 줄이면 중간 비선형 특징 수가 감소하고, 행렬을 저랭크로 만들면 그 폭을 유지하는 대신 입출력 변환 방향이 제한된다. 한편 모든 토큰이 사용하는 shared FFN이 존재하면 두 제약의 손실이 달라질 수 있다. 본 연구는 같은 총 파라미터와 주어진 학습 토큰 예산에서 shared 용량을 바꾸며 넓은 저랭크 routed FFN과 예산이 같은 좁은 dense routed FFN을 비교한다. 이를 통해 shared에 용량을 더 배분할 때 routed를 줄이는 방식도 달라져야 하는지 조사한다. 품질 차이가 발견되면 활성 계산량, 입력별 routing의 가치, 초기화와 학습 길이를 구분해 그 적용 범위를 확인한다. 현재 두 초기화에서 shared 쪽으로 재배분한 모델의 손실이 더 낮았지만, 저랭크 방식의 고유 이득과 계산 효율은 아직 확인되지 않았다.

## 10. Attention Is All You Need에서 적용할 기준

[원문 §1, §3.2, §3.5, §4, §6.2](https://arxiv.org/html/1706.03762v7)는 순차 계산의 제약을 문제로 놓고 병렬성·의존 경로 길이·연산량을 비교한다. scaling과 위치 표현의 이유를 설명하고 설계 변형도 평가한다. 동시에 sinusoidal과 learned 위치 표현이 비슷한 결과였다고 보고한다.

여기서 가져올 기준은 **모든 선택이 유일하게 옳다는 증명**이 아니다. 해결할 문제, 선택의 예상 작용, 합리적인 대안, 그 설명이 틀렸을 때 바꿀 판단이 이어져야 한다는 것이다.

현재 연구에서 그 연결은 다음과 같다.

> 저장 예산 때문에 routed 용량을 줄여야 한다 → rank 제한과 폭 축소는 서로 다른 정보를 제한한다 → shared 용량이 두 제약의 대가를 바꿀 수 있다 → 예산이 같은 LR/DW와 shared 반응을 비교한다 → 이득이 있으면 비용·routing·학습 조건으로 설명의 범위를 좁힌다.

**아직 “저랭크여야 한다”는 답은 없다. 이제 그 선택이 필요한지 판정할 수 있는 질문과 대조가 있다.**

## 부록: 초기화 진단 재현 코드

프로젝트 루트의 기존 환경에서 실행한다. 파일 저장·optimizer step·데이터 다운로드가 없다. 합성 입력이므로 연구 품질 지표로 사용하지 않는다.

~~~python
import math
import torch
from src.model import SharedExpertGroup

torch.set_num_threads(2)
g = torch.Generator().manual_seed(20261113)
x = torch.randn(512, 384, generator=g)
x = x / x.square().mean(-1, keepdim=True).sqrt()

for seed in (17, 401, 402):
    for layer in (0, 3, 5):
        rms = {}
        for count in (2, 5):
            group = SharedExpertGroup(384, 256, count)
            group.reset_parameters(
                seed, f"blocks.{layer}.moe.shared", 1 / math.sqrt(12)
            )
            with torch.no_grad():
                rms[count] = group(x).square().mean().sqrt().item()
        print(seed, layer, rms[2], rms[5], rms[5] / rms[2])
~~~
