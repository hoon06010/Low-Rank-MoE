# M0 implementation interfaces (2026-09-25)

Authority: `experiment_plan.md` v0.2 and `plans/plan.md` §4. This file fixes exchange formats for the preparation code. It does not report experimental results.

## Architecture config

`configs/architecture_grid.json` contains a `conditions` list of 11 objects and separate `proposals` for r=80/16. Every condition has `config_id`, `family` (`LR`, `DW`, `SHARED_ONLY`), `cell` (`HS`, `HL`, `LS`, `LL`, `M`, `SHARED_ONLY`), `layers`, `d_model`, `heads`, `routed_experts`, `top_k`, `routed_width`, `rank`, `shared_width`, `vocab_size`, `context_length`, `seed`. LR uses routed width 768 and factor rank; DW uses dense routed width `3*rank` with `rank` as a budget label only. SHARED_ONLY has zero routed experts, top_k, routed_width and rank. Positive integer shapes and `d_model % heads == 0` are required. Zero shared width is permitted only for an explicitly separately costed boundary. Config identity is the SHA-256 of canonical JSON (`sort_keys=True`, compact separators), excluding `config_hash` itself.

`src.budget` supplies a pure `parameter_counts(config)` returning named whole-model and per-layer total/active counts, and `build_grid()` returning the 11 objects. Ledger CSV lives at `results/preflight/parameter_ledger.csv` with algebraic provenance and separate `total_equal_to_HS` and `active_equal_to_HS` flags. No algebraic row is `measured`.

## Model and batch

`src.model.MoETransformer(config)` accepts the config object. `forward(input_ids, attention_mask=None)` returns `(logits, router_aux_loss, routing_stats)` where logits are `[B,T,V]`, auxiliary loss is a scalar tensor, and routing stats is a dict containing at least valid-token count, per-expert selected count and mean probability. All logits positions may be computed, but padding contributes to neither router statistics nor CE. Top-K is 2 for routed configurations; selected weights sum to one for each valid token. `SHARED_ONLY` returns zero auxiliary loss and empty expert statistics.

Batch dict keys are `input_ids`, `labels`, `attention_mask`, each `[B,T]`. The data builder forms next-token labels once: `labels[b,t]` is the next token for `input_ids[b,t]`, and is `-100` for padding or document boundaries where next token is unavailable. The model and training code do not shift again. `attention_mask` is 1 for real input positions. `valid_target_count = (labels != -100).sum()` is the sole training token counter and evaluation CE denominator. For an optimizer step containing microbatches `i`, the train objective is `(Σ_i CE_sum_i / Σ_i n_i) + 0.01 × (Σ_i n_i router_aux_loss_i / Σ_i n_i)`, where `n_i` is that microbatch's valid target count and `router_aux_loss_i` comes from its own model forward. This per-microbatch auxiliary mean can differ from recomputing MoE load balance over the concatenated optimizer batch. Fix the microbatch partition and `gradient_accumulation_steps` as part of each recipe; do not interpret changes to them as pure architecture effects. Evaluation reports CE alone, in nats per target.

## Checkpoint and cursor

A training checkpoint contains canonical config and hash, source revision, data manifest hash, tokenizer revision, model/optimizer/scheduler/scaler state (scaler may be null on CPU), Python/NumPy/torch CPU and used-device RNG state, data order/epoch/cursor, valid trained-target count, optimizer step, and latest verified checkpoint ID. Save to a temporary file and replace atomically. Resume rejects config, data or source identity mismatch unless an explicitly separate run is created. A failed NaN/Inf run records its failure and retains the last finite checkpoint.

## Run manifest and metrics

One `run_id` identifies one attempt and is unique across success/failure. JSONL run-manifest record requires `run_id`, `protocol_id`, `config_id`, `config_hash`, `family`, `cell`, `seed`, `recipe_id`, `data_manifest_hash`, `eval_revision`, `tokenizer_revision`, `source_commit`, `checkpoint_id`, `checkpoint_step`, `trained_target_tokens`, `status`, `reason`, `source_kind`. `status` is `completed`, `failed`, or `incomplete`. `source_kind` is `measured` or `synthetic_fixture`. `source_commit` may be `unavailable` in this non-repository project, but is never silently invented. The first real study must replace it with a traceable source revision. For `measured` runs, `eval_revision` is the lowercase SHA-256 of a frozen, ordered evaluation target/label manifest generated during the real-data audit; equal values mean the same evaluated target set, and the manifest/checksum must be retained. Synthetic fixtures may use a stable named fixture revision. A matching revision string without that underlying manifest is not proof of equal evaluated targets.

Metrics CSV has the exact required columns `run_id,protocol_id,config_id,family,cell,seed,split,checkpoint_id,trained_target_tokens,eval_target_tokens,loss_nats,status,source_kind`; an optional `eval_revision` is allowed but must agree with the joined manifest. `split` is `train`, `dev`, or `test`; analysis defaults to `dev` and `measured`. `eval_target_tokens` counts unmasked target positions used by CE; positive for a usable row. `loss_nats` is finite and nonnegative for completed evaluation. Failed rows remain in the manifest and cannot fill a seed block. Primary key for a metric is `(run_id, split, checkpoint_id)`; a duplicate is an error, never an extra seed.

`src.analyze` joins on `run_id` and confirms all repeated identity fields match. A contrast uses a complete seed block with equal `protocol_id`, data manifest hash, tokenizer/evaluation revisions, split and trained-target endpoint across its required cells. LR and DW may carry different family recipes; output prints both recipe IDs. Different checkpoints, tokens or permutations of the same run are not independent seeds. CLI default rejects `synthetic_fixture`; tests opt into it explicitly. Incomplete or duplicate blocks are reported with reasons and excluded per contrast.

## Output locations

Source: `src/`; tests: `tests/`, test-only fixtures: `tests/fixtures/`; algebraic and toy outputs: `results/preflight/`; verified test logs and hashes: `reports/verification.md`; real-data manifests when approved: `data/manifests/`. `results/preflight/` must label every synthetic value. No preflight value may enter manuscript Results as a measured effect. `plans/runbook.md` separates commands already executed from future conditional commands.
